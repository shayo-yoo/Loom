# CHG-20261118-001

- Date: 2026-11-18 (Asia/Shanghai)
- Type: FEATURE, API
- Status: Implemented and verified in ST browser session
- Requirement / motivation: Start development from the user's acceptance target: an extension project visible in SillyTavern.
- Changes:
  - Added a standard ST extension manifest at the Loom repository root.
  - Added a Core in-memory extension/capability registry with execution, duplicate/argument checks, and extension cleanup.
  - Added a Loom UI panel adapter which registers itself, exposes a launcher in ST's extension wand menu, and lists registered capabilities.
  - Added Node tests for registry behavior and initial governance documents/API index.
  - Created a directory junction from ST's third-party extension directory to the Loom workspace.
  - Started ST on port 8100 and verified it with Chrome headless.
- Direct scope: `manifest.json`, `package.json`, `Loom Core/index.js`, `Loom Core/index.test.js`, `Loom UI/index.js`, `Loom UI/style.css`, `docs/engineering-governance/`.
- Horizontal impact:
  - SYNC: Core/UI shared contract, represented by the `globalThis.Loom` API and API index.
  - ADAPT: SillyTavern third-party loader; it consumes manifest fields `display_name`, `loading_order`, `js`, and `css` without ST core changes.
  - NO-CHANGE: SillyTavern core and other extensions; this feature is isolated to Loom and the extension discovery directory.
  - CONFIRM: Extension disable/enable persistence was not independently exercised; ST manifest activation, menu entry, and panel interaction were verified.
- Architecture/API/data: Adds a public browser-global API; registry data is volatile and in-memory. No persistence or host data writes. Capability execution is trusted-code execution, not a security sandbox.
- Compatibility/migration: New extension; no existing Loom API or data to migrate. ST extension discovery remains the compatibility boundary.
- Validation:
  - `npm test`: pass, 3 tests.
  - `node --check "Loom Core/index.js"` and `node --check "Loom UI/index.js"`: pass.
  - ST `GET /api/extensions/discover`: HTTP 200 and includes `third-party/Loom`.
  - HTTP 200 for manifest, UI JS, Core JS, and CSS under the third-party extension path.
  - Chrome headless: loaded Loom module, found `#extensionsMenu` and the Loom launcher, clicked it, confirmed panel open, runtime version 0.1.0, one registered UI extension, zero capabilities, no Loom console error.
  - Responsive layout check at 1365px and 390px: no horizontal overflow.
  - Chrome logged unrelated 404s and a Bot Browser remote index error from other installed extensions; these were not attributed to Loom.
- Risks / outstanding: No schema validation, permission model, persistence, compatibility negotiation, or final replaceable UI abstraction yet. ST startup warns that `listen: true` binds `0.0.0.0` while private request filtering is disabled; this existing user config was not altered. Browser interaction validated the initial panel path, but extension enable/disable persistence and full visual screenshot review were not covered. User-provided ST working changes remain untouched.
