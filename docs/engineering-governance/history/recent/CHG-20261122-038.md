# CHG-20261122-038

- Date: 2026-11-22 (Asia/Shanghai)
- Type: FEATURE, API, TEST, DOCS
- Requirement / motivation: the panel had grown into one long column (status rows, extension registry, host snapshot, permissions, events, and capabilities all expanded), which the user reported as hard to use on a phone; and the management surface still lacked a way to pick up a newly dropped package without reloading, or to revise a saved script. This round covers both.
- Stage: next increment, branch `feature/panel-sections-and-management`.

## Collapsible sections

- The panel content is now split into `<details class="loom_section">` blocks: **安装与扩展** and **脚本** default open (the two places users act), and **扩展状态**, **宿主环境**, **权限**, **事件监听**, **公开能力** default collapsed. Status counters stay visible above the sections.
- Built-in sections are declared in the panel template; mounted sections (installer, scripts) are wrapped by `wrapMountedSection`, which moves their existing markup into a body and turns the heading into the summary — no duplicated markup.
- Open/closed state is persisted per section in `loom-ui` state (`panelSections`) on the `toggle` event, so the panel reopens the way the user left it, on phone and desktop.
- Styling lives in `style.css` (`.loom_section`, `summary`, `.loom_section_body`), matching the panel's existing border/colour variables.

## Rescan packages

`LoomUI.rescanExtensions()` re-reads `extensions/index.json`, rebuilds the bundled list, and imports anything new or not yet active — skipping disabled packages. The installer section has a 重新扫描 button. This closes the "I added a folder and ran the index script, now what" loop without a page reload.

## Edit a saved script

The script list gained 编辑: it loads the record's name and source into the form and switches the save button to 保存修改. Saving calls `updateScript` (which reverts to the previous source if the new one fails to load), then clears the form. Deleting the script being edited also resets the form state.

## Direct scope

`Loom UI/index.js`, `Loom UI/style.css`, `tests/browser/verify.mjs`, API index, guide, project state, CHANGELOG, version markers.

## Horizontal impact

- SYNC: `renderPanel` still only fills the elements inside sections; every `getElementById` target from before is unchanged, so the render functions did not need to move.
- SYNC: `applySectionState` runs after the mounted sections exist, and again is safe to call later (it only binds `toggle` once per section via `data-bound`).
- ADAPT: the browser harness gained a `panel sections` probe: counts sections, asserts default open/closed, toggles 权限 and checks persistence, calls rescan, and drives 编辑 → 保存修改 through the real DOM (asserting the edited behaviour and that no duplicate script is created).
- NO-CHANGE: extension enable/reload/remove, script enable/disable, capabilities, host adapter.

## Verification

- `npm test`: 244 tests pass (UI-only change; covered by the browser probe).
- `npm run verify:browser`: **182/182 checks pass**, twice consecutively. New: seven collapsible sections with correct defaults; a toggle persists to `loom-ui` state; rescan returns both bundled packages with no problems; editing a script through the buttons changes its behaviour (`MIXED` → `mixed?`) without creating a second record. The phone hit-test first closes any SillyTavern dialog (an open modal leaves the page inert, so every point misses), then hides residual overlays and records what was blocking, so a real panel failure stays distinguishable.

## Risks / outstanding

- Section state is UI state and is included in the settings save; a very large section map is still tiny.
- Rescan replaces the bundled source list; a package removed from `index.json` keeps running until the page reloads (no unload-on-absence yet).
- Editing a script changes only its source; the generated id and name keep their original values (renaming is not implemented).
- `<details>` rendering is browser-native; the panel relies on it rather than a custom accordion, which keeps the implementation small but gives no animation.
