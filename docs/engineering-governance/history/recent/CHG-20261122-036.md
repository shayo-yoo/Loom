# CHG-20261122-036

- Date: 2026-11-22 (Asia/Shanghai)
- Type: FEATURE, API, TEST, DOCS
- Requirement / motivation: extension packages gained an enable/disable switch in CHG-20261122-034, but scripts only had "delete". A script that should pause — or one being iterated on — had to be destroyed to stop it. This closes the symmetry between packages and scripts.
- Stage: next increment in the same round as the mobile fix.

## Changes

- Script records gain `enabled` (default true; records saved before this change have no flag and are treated as enabled — `normalizeScriptRecords`).
- `LoomUI.setScriptEnabled(id, enabled)` → disabling unloads the extension and keeps the source; enabling re-runs it. A failed run is rejected and leaves the previous record untouched.
- Boot runs only enabled scripts; a disabled script stays listed in the panel as `已停用`.
- The panel row gains a 启用/停用 toggle next to 重新运行 and 删除.
- `readScripts` delegates to the pure `normalizeScriptRecords` helper, which also drops records without an id or source.

## Direct scope

`Loom UI/index.js`, `Loom UI/installer.js`, `Loom UI/installer.test.js`, `tests/browser/verify.mjs`, docs, version markers.

## Horizontal impact

- SYNC: `normalizeScriptRecords` is the single place that decides what a valid persisted script is; `readScripts` must not re-implement it.
- SYNC: the panel's script row grew a third button; the browser probe addresses buttons by their text, so no selector was tied to button order.
- NO-CHANGE: `saveScript` still imports before persisting; `updateScript` still reverts on a failed load; deletion is unchanged.

## Verification

- `npm test`: **244 tests pass** (243 before; +1 normalisation test covering default-enabled, explicit disabled, and invalid records).
- `npm run verify:browser`: **174/174 checks pass**. New: disabling a script unloads it but keeps the record (and the flag is flushed to host settings); after a reload it is still listed but not registered; enabling runs it again and the capability answers; deletion then removes it. The probe waits for the real `/api/settings/save` before reloading instead of sleeping.

## Risks / outstanding

- Scripts remain unsandboxed and their source is stored in SillyTavern settings (unchanged; recorded in CHG-20261122-034).
- A disabled script's code may still be resident in the browser module map for the session; disabling is logical, like packages.
- There is no "run once" or scheduling semantic; scripts are activate-on-boot hooks.
