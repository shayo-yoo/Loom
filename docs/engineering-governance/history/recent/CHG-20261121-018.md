# CHG-20261121-018

- Date: 2026-11-21 (Asia/Shanghai)
- Type: FEATURE, API, REFACTOR, TEST, DOCS
- Requirement / motivation: UI requirements §3 requires the UI to respond to data changes, §4.3 requires composite components whose instances keep independent state, and §5 requires declarative structures that can be regenerated. CHG-20261121-016 recorded the last structural limitation explicitly: "no subtree reconciliation (child-list changes rebuild the whole view)", so any list update threw away every item's DOM, focus and component state. This change replaces the render model with an entry tree and adds keyed reconciliation.
- Stage: UI engine polishing, second increment (self-planned goal `goal-957b8a59`).

## New rendering model (`Loom UI/views.js`)

A mounted view is now an **entry tree**: every rendered node keeps its element, resolved props, validated node, child entries and lifecycle registrations, plus a parent link and index. `record.mounts` (path → entry) is a rebuilt index over that tree, used by `setProps`, focus capture and the public handles.

Structural operations became incremental:

| Operation | Before | Now |
|---|---|---|
| `setProps` on a component without `update` | rebuilt the whole view | rebuilds only that subtree |
| `setChildren` | rebuilt the whole view | reconciles children by key, then by index + component |
| `appendChild` | rebuilt the whole view | mounts only the new child |
| `remove` | rebuilt the whole view | disposes only that subtree |
| `setRoot` | rebuilt everything | still rebuilds everything (the one legitimate full swap), restoring focus/selection/scroll by path |

Reconciliation matches a child by `key` when present, otherwise by `index + component id`. A matched child whose props changed is updated through its `update`; a matched position whose component id changed is remounted; unmatched old children are disposed (leaves first, then `onCleanup`, then `unmount`); the new order is applied by re-appending.

## Keyed children (`Loom UI/view-tree.js`)

- Nodes accept an optional `key`: a non-empty string or a finite number. Duplicate sibling keys are rejected, because matching would silently move the wrong element.
- `key` is omitted from normalized/described output when absent, so existing tree shapes and assertions are unchanged.
- `serializeNode` **keeps** the key (structure, not behaviour), so a serialized list still carries identity across a re-mount.

## Focus across reorders

Re-appending a node moves it in the DOM, which blurs a focused element even though the same element object is reused. The reconciler captures the focused element **by identity** (plus text selection) before reordering and restores it afterwards. This was found by the browser probe, not by the DOM stand-in: the stand-in keeps `activeElement` across moves, so unit tests passed while real Chrome lost focus.

## Horizontal impact

- SYNC: `Loom UI/index.js` facade — no signature change; `createView`, `setProps`, `serializeView` keep their contracts.
- SYNC: components untouched; `update`, `unmount`, `onCleanup`, `onMount` keep their semantics. Slot containers (`tabs`) still work because every entry remembers its `content` resolver.
- ADAPT: two `views.test.js` cases asserted that a no-update `setProps` rebuilds the whole root; the contract is now stronger (only the target subtree), so the assertions were updated to the new guarantee rather than loosened. A third test used `setChildren` to trigger a full rebuild; it now uses `setRoot`, which is the operation that still disposes a whole tree.
- ADAPT: `normalizeNode`/`validateNode` omit `key` when absent, so existing `describe()` shapes and the view-tree tests stay valid.
- NO-CHANGE: `Loom Core/*`, `Loom Host/*`.
- CONFIRM: whether `tabs` should become fully controlled. Left as-is: it switches locally and emits `change`, and `describe()` reports the declared `active`; documented rather than changed, because a controlled-only `tabs` needs a consumer that manages state.

## Validation

- `npm test`: **161 tests pass** (152 before; +9). New coverage: keyed reorder reuses elements and disposes nothing, keyed insert/remove touches only affected items and disposes in document order, keyed prop change updates in place, unkeyed children match by index + component, a component swap at one index remounts it, `appendChild`/`remove` leave siblings untouched, duplicate and invalid keys are rejected, keys survive serialization, subtree rebuild preserves sibling state, `setRoot` still restores focus/selection/scroll, disposal order is leaves-first.
- `npm run verify:browser`: **75/75 checks pass** against a live SillyTavern. New checks: a keyed list reordered in a real browser keeps the same elements, applies the new order and **keeps focus in the moved element**, and an insert leaves the neighbours' elements untouched.
- The focus bug fixed above was surfaced only by the browser probe; it would have shipped as "reorders lose focus" otherwise.

## Failed checks and corrections (recorded, none hidden)

1. The engine rewrite initially kept two old tests green by accident and broke four others that encoded the previous whole-view-rebuild semantics. Each was re-examined: three were updated to the deliberately stronger contract, and one was rewritten to exercise `setRoot` because that is now the only full-tree path.
2. `normalizeNode` emitted `key: undefined`, which broke a deep-equal test on the normalized shape. Omitted-when-absent was chosen instead of updating the assertion, keeping the public shape stable.
3. The props rollback on a throwing `update` was lost during the rewrite, caught by the safer-image test. Restored in the new `setProps`.
4. `setRoot` ran mount callbacks before the new root was attached, so `focus()` did nothing (`fresh:false`). Fixed by mounting detached, swapping, then reindexing and running callbacks.
5. Focus was lost on keyed reorders in Chrome (see above); fixed by identity-based focus capture inside the reconciler.

## Risks / outstanding

- Reconciliation matches by key or index+component; it does not move subtrees between containers, and it has no "move" optimisation — a full reversal re-appends every node (correct, but O(n) DOM moves).
- Only props trigger an in-place `update`; handlers are re-bound through the entry's current node (verified by a test), but a matched child whose handler closure captured outside state still needs a remount to change that closure.
- Element-level scroll positions of moved items are not preserved (only focus/selection are).
- No virtualisation or windowing; every item is a real DOM node.
