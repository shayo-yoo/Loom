# CHG-20261121-017

- Date: 2026-11-21 (Asia/Shanghai)
- Type: FEATURE, API, FIX, TEST, DOCS
- Requirement / motivation: CHG-20261121-016 recorded the missing piece directly: "the view engine has no unmount hook — which blocks document-level listeners (menus that close on outside click, tooltips)". A component that attaches a listener on `document` had no way to remove it, so any interactive overlay leaked; and `mount` ran before the tree was attached, so a component could not focus or measure anything. This change adds the missing lifecycle so components can own external listeners and post-attach work, then proves it by upgrading `modal`.
- Stage: UI engine polishing, first increment.

## New engine contract (`Loom UI/views.js`)

Mount context gains two registration hooks:

- `context.onCleanup(fn)` — teardown for when the node leaves the DOM (view destroyed, root replaced, structural change rebuilt the tree). Cleanups run **most recent first**, before the component's `unmount`, and a throwing cleanup is reported without stopping the others. Entries are disposed once (idempotent), children before parents.
- `context.onMount(fn)` — work that needs a *connected* element (focus, measurement). Runs after the tree is appended, parent-first, once per mount; not re-run by in-place `setProps`, re-run after a structural rebuild.

A component may now declare `unmount(element, props, context)`. This required a registry fix: `components.js` had never stored `unmount`, so the engine's call found nothing — the field was validated and stored now.

Disposal is wired into `renderRecord` (before the swap, after render state is captured), `view.destroy()`, `destroyAllViews()` and `resetViews()`.

## Component changes

- `modal`:
  - Escape is handled by a **document-level** `keydown` listener, registered through `onCleanup`, so it works wherever focus sits and cannot outlive the view. The previous element-level listener only worked when the dialog itself had focus.
  - Focus moves into the dialog on open — including when the modal is created already open — via `onMount`, because `mount` runs before attachment and `focus()` on a detached element does nothing.
  - Closing (or unmounting) restores focus to the opener when it is still connected.
  - Tab / Shift+Tab wrap between the dialog's focusable controls; with no focusable control, focus stays on the dialog.
  - Focusable elements are queried one selector at a time (the unit-test DOM stand-in does not split selector lists) and filtered by the `tabindex` *attribute* plus `disabled`/`hidden`, because the `tabIndex` property defaults differ between browsers and the stand-in.
- `card`: an empty `title`/`subtitle` is now hidden instead of leaving a blank node (recorded as a pre-existing wart in CHG-20261121-016).
- `style.css`: fixed three pre-existing selector typos that meant those rules never applied — `.loom-capability_id` → `.loom_capability_id`, `.loom-identity_member code` → `.loom_identity_member code`, `.loom-panel_actions .menu_button` → `.loom_panel_actions .menu_button`.

## Horizontal impact

- SYNC: `components.js` — `unmount` is validated and stored; without this the hook silently no-ops.
- SYNC: `dom-fixture.js` gained document-level `addEventListener`/`removeEventListener`/`dispatchEvent`/`listenerCount`, mirroring a real document. The stand-in was incomplete, not the engine.
- ADAPT: two modal tests dispatched Escape on the element; they now dispatch on the document, which is how a keydown actually reaches the handler. The assertion intent (Escape closes) is unchanged.
- NO-CHANGE: `createView`, `serializeView`, `setProps` signatures; all additions are new keys on the context and a new optional component field.
- NO-CHANGE: `Loom Core/*`, `Loom Host/*`; the panel does not mount modals yet.
- CONFIRM: whether `menu` should become a dropdown with `open` + outside-click dismissal. Not done — the current `menu` is a persistent menubar, and inventing an `open` prop without a consumer would be speculative.

## Validation

- `npm test`: **152 tests pass** (149 before; +3 net after adjusting two existing tests). New coverage: cleanups run on destroy and on structural rebuild, children disposed before parents, a throwing cleanup still runs the rest and `unmount`, in-place updates do not dispose, `onCleanup`/`onMount` argument validation, `onMount` runs once with a connected element and again after rebuild, a throwing `onMount` does not break the view, modal Escape via document + listener removal on destroy, Tab/Shift+Tab wrapping, focus restore, detached-opener handling, and card empty-title hiding.
- `npm run verify:browser`: **71/71 checks pass** against a live SillyTavern. New browser checks: a probe component's document listener fires while mounted and is removed by `onCleanup` on destroy; a modal moves focus into the dialog on open, closes on a document-dispatched Escape, restores focus to the opener, and stops reacting after `destroy()`.
- The React-style claim "cleanup runs before the DOM is swapped" is exercised by the rebuild test, which asserts disposal order across a live view.

## Failed checks and corrections (recorded, none hidden)

1. The first run failed because `components.js` discarded `unmount`; the engine called a hook that never existed on the record. Fixed at the registry, not worked around in the component.
2. The fixture's `document` had no event methods, so the modal threw `ownerDocument.addEventListener is not a function`. The stand-in was extended to model a real document rather than adding defensive branches to the component.
3. Two existing modal tests dispatched Escape on the element; with a document-level listener they no longer reached the handler. The dispatch target was corrected to the document (matching real key events), not the implementation weakened.
4. The modal's focus trap initially found no focusable elements because the fixture does not parse comma-separated selector lists, and later because it reported `tabIndex === -1` for every element. Both were adaptation issues: selectors are now queried individually and filtered by the `tabindex` attribute.
5. The browser probe caught a real ordering bug: focusing the dialog during `mount` failed because the tree was not yet attached. Fixed by adding `onMount` (the missing half of the lifecycle) rather than deferring with a timer.

## Risks / outstanding

- Cleanups are not run when a component's `update` throws (nothing is disposed; the tree is rolled back), which is correct but means a component that failed mid-update keeps its listeners until the next structural change or destroy.
- `onMount` callbacks are not re-run when only an ancestor is re-created; they run per node mount, which is what a rebuild produces.
- Structural changes still dispose and re-create the entire subtree, so a focus trap held by a parent is re-established rather than preserved.
- `modal` has no focus sentinel for screen readers and no `inert`/`aria-hidden` on the rest of the page.
- The engine still has no keyed list rendering or subtree reconciliation; a large list rebuilt by `setChildren` will lose per-item state.
- `tabs` continues to keep local selection state independent of the declared `active` prop.
