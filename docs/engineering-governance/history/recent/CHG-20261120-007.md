# CHG-20261120-007

- Date: 2026-11-20 (Asia/Shanghai)
- Type: FEATURE, API, UI, TEST, DOCS
- Requirement / motivation: Provide a second, discoverable Loom entry inside SillyTavern's extension settings panel, and lay mobile-friendly groundwork so future phone adaptation does not require reworking layout structure.
- Changes:
  - Added `Loom UI/settings.js`: a pure `buildSettingsEntryHtml(summary)` builder plus `summarizeForSettings`, rendering an ST-style inline drawer (`#loom_settings_entry`) with version, extension/capability counts, conflict count, host status and an "open Loom panel" button.
  - Added `Loom UI/dom.js` with the shared `escapeHtml` helper (moved out of the entry file).
  - UI entry installs the settings drawer into `#extensions_settings`, keeps its values fresh after panel refreshes, and retries until both entries exist.
  - Deliberately did **not** bind a click handler on `.inline-drawer-toggle`: SillyTavern already binds a global handler (`script.js`), and a second listener caused a double toggle (open→closed).
  - Added host capability `viewport.get` returning `{ width, height, pixelRatio, isMobile }` with a `matchMedia`+width fallback.
  - Panel now shows a "视口" row.
  - Mobile-safe layout work: panel/drawer use fluid widths, the body is a single flex column with a sticky header and its own scroll area, safe-area insets are respected, tap targets are ≥44px, long identifiers wrap, and the `grid` component gained a `responsive` prop (default true) that collapses to one column at ≤768px via the `--loom-columns` CSS variable.
  - Bumped Core/manifest/package version to 0.7.0.
- Direct scope: `Loom UI/settings.js`, `Loom UI/dom.js`, `Loom UI/index.js`, `Loom UI/builtin-components.js`, `Loom UI/style.css`, `Loom UI/settings.test.js`, `Loom UI/dom.test.js`, `Loom UI/components.test.js`, `Loom Host/index.js`, `Loom Host/index.test.js`, `Loom Core/index.js` (version only), `manifest.json`, `package.json`, governance docs.
- Horizontal impact:
  - SYNC: Host capability list grows to four; the exact-list assertion in the host test was updated (not relaxed).
  - ADAPT: Panel markup changed from `panel > header + body` to `panel > body > header + content`; all panel ids were preserved, so `renderPanel` and tests keep working.
  - NO-CHANGE: SillyTavern source; the drawer reuses ST's own global handler and CSS classes.
  - CONFIRM: Visual review on a real phone (not just emulated metrics) is still outstanding.
- Architecture/API/data: Adds `viewport.get` (read-only) and documents mobile constraints in the API index. No storage or contract changes.
- Compatibility/migration: New capability and new UI element; no removals. `escapeHtml` moved to `dom.js` and re-imported, no behavior change.
- Validation:
  - `npm test`: pass, 41 tests (Core 19, Host 7, UI components 6, view-tree 5, settings 3, dom 1 — plus manifest/version checks) covering settings markup/escaping, viewport capability across desktop/mobile/fallback, and the responsive grid descriptor.
  - `node --check` for Core, Host and all UI modules: pass.
  - Chrome (ST 8100): both entries present; settings drawer collapsed → expanded → collapsed correctly; the drawer button opened the panel; settings values were current (`0.7.0`, host "已连接 SillyTavern").
  - Desktop 1280px: 3-column grid (3×~421px), panel width 440px.
  - Mobile emulation 390×844: grid collapsed to one column, panel width 390px (full width), zero elements overflowing `innerWidth`, `viewport.get` reported `{width:390,height:844,pixelRatio:2,isMobile:true}`.
  - No Loom-related console errors in either viewport.
- Failed checks and corrections (all recorded, none hidden):
  1. Media query used `var(--loom-mobile-breakpoint)`; media queries cannot read CSS variables, so the rule never applied. Replaced with literal breakpoints.
  2. `grid` set `gridTemplateColumns` inline, which always beats media queries, so responsive collapse never happened. Switched to the `--loom-columns` custom property with a CSS fallback.
  3. Adding our own `.inline-drawer-toggle` listener double-toggled the drawer (ST already handles it). Listener removed and the constraint documented.
  4. Panel body rendered 206px wide on mobile because `.loom_panel` was a flex row with `header` and `body` as siblings, shrinking the body. Markup restructured so the body is the only flex child.
  5. Settings drawer showed a stale host status because it updated before the async snapshot resolved; it now refreshes after the snapshot promise settles.
  6. An earlier verification run reported both entries missing; the cause was SillyTavern not running (Chrome connection-error page), not a code defect — confirmed with the user, who also confirmed the wand entry was visible.
- Risks / outstanding: Emulated mobile metrics are not a substitute for real-device testing; touch gestures, keyboard-driven viewport changes, and list virtualization are not implemented. Breakpoints are duplicated between JS/CSS constants by necessity and must be kept in sync manually.
