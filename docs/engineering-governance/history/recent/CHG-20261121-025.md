## Changes

### `characters.update` (write, `host.chat.write`)

`{ avatar, description?, firstMessage?, exampleMessages?, tags? }` 鈫?`{ avatar, name, updated, refreshed }`.

- The card is addressed by `avatar` (the PNG filename), because that is the stable key SillyTavern itself uses for a card; `name` is display text and may repeat.
- **Only the fields that were sent are written.** A field that is not present in the input is untouched; a field explicitly set to `''` is cleared. `updated` lists exactly the fields that changed, in a fixed order (`description`, `firstMessage`, `exampleMessages`, `tags`), so a caller can tell "wrote nothing" from "wrote an empty value".
- The write goes through SillyTavern's own `/api/characters/merge-attributes` endpoint (the same one the host's own editor uses), **not** a hand-rolled PNG chunk rewrite. The endpoint deep-merges into the card's V2 `data` block; SillyTavern normalises that block over the legacy top-level copy whenever it reads the card, so both views stay consistent in the UI. The adapter does not write the legacy top-level copy 鈥?doing so would be a second source of truth that the host itself does not maintain.
- The in-memory `context.characters` copy is refreshed through the host's `getCharacters()`. A card that the host still shows with the old text after the write fails with `CHARACTER_UPDATE_FAILED` rather than reporting a silent success.
- Tags are normalised before writing: each trimmed, empty ones dropped, duplicates removed, order preserved.

## Horizontal impact

- SYNC: host capability list (20 鈫?21); the write-capability table in `API_INDEX.md` gains the new row, and the character section documents the merge-attributes behaviour.
- ADAPT: the browser probe writes a scratch card through `characters.update`, then parses the PNG's `chara` tEXt chunk and asserts the V2 `data` block carries the edited text 鈥?the card is never shown to the user, and the scratch card is deleted afterwards.
- NO-CHANGE: `characters.list`/`characters.get`; the character write does not touch chat or world books.
- **Known limitation:** the legacy top-level copy inside the PNG keeps the old text. Third-party tools that read V1 fields without the V2 `data` block will see stale values; that is the host's own behaviour (`merge-attributes` writes the V2 block), not an adapter workaround.
