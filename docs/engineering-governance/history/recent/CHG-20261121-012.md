# CHG-20261121-012

- Date: 2026-11-21 (Asia/Shanghai)
- Type: TEST, FIX, API, DOCS
- Requirement / motivation: CHG-20261120-008, -009, -010 and -011 each recorded the same outstanding item: the work was verified only against stubbed host contexts, never in a running browser. `AGENTS.md` rule 12 and the governance quality gate both require real execution, not just "it compiles and the unit tests pass". This change closes that gap with a repeatable browser harness, and records the two real defects the harness found.
- Stage: verification stage, executed before the next feature increment (per the plan agreed after CHG-20261121-011).

## New verification harness

`tests/browser/verify.mjs` (+ `npm run verify:browser`) starts headless Chrome, connects over the DevTools protocol with Node's built-in `WebSocket`, loads the running SillyTavern, and drives the real extension. 38 checks across six groups:

1. **Runtime** — `window.Loom` present, version matches the served extension manifest (read at run time, not hard-coded), capability/extension counts, `loom-host` + `loom-ui` registered.
2. **Entries** — wand-menu launcher, settings drawer, and the host containers it attaches to.
3. **Panel** — opens from the launcher, reports "已连接 SillyTavern", shows live viewport metrics, lists 14 capability contracts, shows `worlds.entry.update` and its `host.worldinfo.write` requirement, and renders the settings/chat/world permission rows.
4. **Live reads** — `worlds.list` (80 books), `characters.list` (107 characters), `characters.get` on a real card with no leaked internals, `context.snapshot`, `viewport.get`, `worlds.entries` on a real book (7 entries), and omitted-input handling.
5. **Permission flow** — a probe extension is denied `chat.messages` and `worlds.entry.update` before any grant; the real panel toggle flips the grant; the grant reaches `extensionSettings.__loom`; the gated capability then runs; a granted world write reaches the host and reports `WORLD_NOT_FOUND`.
6. **Reload restore** — the grant survives a page reload, the store stays attached, and a grant belonging to an extension that no longer exists is not applied.

The run mutates state (it grants permissions — that is the behaviour under test) and cleans up afterwards by deleting the `__loom` root and flushing the debounced save. Cleanup is itself a check.

## Defects found by the harness (fixed here)

### 1. Omitting the input argument was rejected by null-input capabilities (`FIX`)

`executeCapability('loom-host', 'worlds.list')` failed with `INVALID_INPUT: $: expected null, received undefined`. Every read capability that takes `null` input was unusable unless the caller passed `null` explicitly — and the natural call shape is to omit it. Capability contracts are JSON, and JSON has no `undefined`; a missing argument means "no input", which is `null`.

Fixed in Core: the input is normalised (`input === undefined ? null : input`) before schema validation and before the handler. A capability that expects an object still fails with a clear message when nothing is passed, because the normalised value is `null`, not a silently fabricated object.

### 2. A missing world book was reported as a missing entry (`FIX`)

`worlds.entry.update` on a non-existent book returned `ENTRY_NOT_FOUND`, contradicting the contract recorded in CHG-20261121-011 and the API index. SillyTavern's `loadWorldInfo` answers an unknown name with no entries at all, which the handler treated as "book exists, entry does not".

Fixed in Host: a book with no entries is reported as `WORLD_NOT_FOUND`, so a caller can tell a typo in the world name from a typo in the entry uid.

## Harness defects found and fixed (test-only)

1. **State-dependent probes.** The first green-looking run depended on grants left behind by an earlier run: the denial checks silently passed as "already granted", and the panel toggle *revoked* instead of granting. Probes now revoke first and assert the flip (`after === !before`) rather than a hard-coded direction.
2. **Cleanup aborted silently.** Cleanup called `revokePermission` after a reload, when the probe extension no longer exists; the first throw aborted the rest and left test grants in the user's settings. Cleanup now edits the store directly, flushes the debounced save, and asserts the root is gone.
3. **Character library probed too early.** `characters.list` returned 0 because SillyTavern loads characters asynchronously; the harness now waits for the library before asserting.
4. **Wrong manifest URL.** The first version fetched `/manifest.json`, which is SillyTavern's PWA manifest and has no `version`. It now reads the extension manifest and honours `LOOM_MANIFEST_URL`.

## Validation

- `npm test`: **pass, 84 tests** (was 83). New: omitted input is treated as `null` (both omitted and explicit `null`); empty-book write reports `WORLD_NOT_FOUND`.
- `npm run verify:browser`: **38/38 checks pass** against SillyTavern on `http://127.0.0.1:8100/` with runtime 0.11.1, headless Chrome, 1264×805 viewport. Only two console errors were recorded, both from the third-party `SillyTavern-BotBrowser` extension (failed master-index fetch), not from Loom.
- Cleanup verified out of band: `settings.json` no longer contains `extensionSettings.__loom` after a run.

## Not covered (recorded, not implied)

- The world **write** path is verified only through the permission gate and the `WORLD_NOT_FOUND` branch. No real book was mutated, because that would alter user data; a write against a scratch book needs a host capability to create one first.
- Visual review is DOM assertions in headless Chrome, not a human looking at layout on desktop and phone. The 0.7.0 visual pass remains the only human-verified layout check.
- `chat.messages` returned 0 messages in one run and 3 in another depending on whether a chat was open; the harness asserts the shape and gating, not specific chat content.
- Mobile emulation is not exercised by the harness.

## Risks / outstanding

- The harness assumes SillyTavern is already running with Loom enabled, and Chrome at the default path (overridable via `LOOM_CHROME`). It fails loudly rather than skipping, which is correct for an explicit command but means it cannot be wired into `npm test`.
- It writes to the user's live `settings.json` during the run. Cleanup restores the previous absence of `__loom`, but a crash mid-run could leave test grants behind; re-running the harness cleans them.
- Headless Chrome may behave differently from a real browser for ST features that need user gestures or media; the harness covers Loom, not SillyTavern.
