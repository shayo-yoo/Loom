# CHG-20261118-003

- Date: 2026-11-18/19 (Asia/Shanghai)
- Type: FEATURE, API, TEST, DOCS
- Requirement / motivation: Start implementing Core's reading responsibility and the host-isolation principle by adding a SillyTavern adapter that exposes read-only host data through Loom capabilities.
- Changes:
  - Added `Loom Host/index.js`, an independent SillyTavern adapter that registers extension `loom-host` and capabilities `context.snapshot`, `characters.list`, and `worlds.list`.
  - Reads only public `SillyTavern.getContext()` fields: `chat`, `characters`, `name2`, `chatId`/`getCurrentChatId`, and `getWorldInfoNames`.
  - Returns defensive copies mapped to primitive fields; no ST objects or internal references are exposed.
  - Loom UI now loads the adapter, shows a "宿主环境" section (connection state, current character, current chat, message count), and calls `context.snapshot` through the public Core API.
  - Added a refresh control to the panel header.
  - Bumped Core/manifest/package version to 0.3.0.
- Direct scope: `Loom Host/index.js`, `Loom Host/index.test.js`, `Loom Core/index.js` (version only), `Loom UI/index.js`, `Loom UI/style.css`, `manifest.json`, `package.json`, `tests/manifest.test.js`, governance docs.
- Horizontal impact:
  - SYNC: Loom UI must load the adapter before displaying host data; the Core public API contract is unchanged apart from the version constant.
  - ADAPT: Capability metadata is now populated with real schemas, so the panel's schema view has live data.
  - NO-CHANGE: SillyTavern source files and other extensions; the adapter only reads `getContext()` fields at call time.
  - CONFIRM: Other host data (chat messages, world entries, settings) intentionally not exposed; no write capability added yet.
- Architecture/API/data: Introduces Host Adapter as a separate module, matching the requirement that host-specific implementation be isolated. Registry data remains in-memory; only read capabilities are registered.
- Compatibility/migration: `loom-host` capabilities are new; no existing caller depends on them. Extension ID and capability IDs follow the documented naming rules.
- Validation:
  - `npm test`: pass, 13 tests (6 Core, 5 Host adapter, 2 manifest/version consistency).
  - `node --check` for Core, UI, and Host: pass.
  - ST serves the new host adapter, manifest, Core, and UI styles with HTTP 200 on port 8100.
  - ST page loaded runtime 0.3.0 with extensions `loom-host` and `loom-ui` and 3 capabilities.
  - Panel showed "已连接 SillyTavern" with live values: character "角色卡创作助手", chat id, 5 messages, 107 characters, 80 worlds.
  - `context.snapshot` rejected a non-null input with `INVALID_INPUT` and path detail; no Loom console errors.
- Failed checks and corrections: A first browser probe read empty results because it evaluated before the page finished loading; a longer wait showed the runtime was fine. The Core test asserting a hard-coded `0.2.0` was replaced with a version-format check plus a manifest/package sync test so future version bumps cannot silently drift. Both findings are recorded rather than hidden.
- Risks / outstanding: `characters.list` reads the full character list and `worlds.list` the full world list; no pagination or filtering yet. Chat message contents and user settings are deliberately not exposed. The adapter assumes `getContext()` shape; ST upgrades may require adapter-only adjustments.
