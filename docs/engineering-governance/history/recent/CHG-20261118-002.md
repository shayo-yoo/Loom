# CHG-20261118-002

- Date: 2026-11-18 (Asia/Shanghai)
- Type: FEATURE, API, TEST, DOCS
- Status: Implemented and verified in ST browser session
- Requirement / motivation: Make cross-extension capability contracts actionable and return structured execution/error results, as required by Core execution and shared interface requirements.
- Changes:
  - Added schema definition checks and a JSON Schema subset for types, enum/const, required/properties, arrays/items, additional properties, numeric ranges, string lengths, and array sizes.
  - Validate input before execution and output after execution.
  - `executeCapability` now consistently returns `{ success: true, data }` or `{ success: false, error: { code, message, details? } }`.
  - Error results distinguish invalid IDs, missing capabilities, invalid input, invalid output, and handler failure.
  - Copy schemas during registration and descriptor listing to prevent mutation through caller-owned schema objects.
  - Updated the Loom panel to expand each capability and show input/output contracts.
  - Bumped Loom package, manifest, and runtime versions to 0.2.0.
- Direct scope: `Loom Core/index.js`, `Loom Core/index.test.js`, `Loom UI/index.js`, `Loom UI/style.css`, `manifest.json`, `package.json`, API and architecture/state docs.
- Horizontal impact:
  - SYNC: Capability callers must consume structured result objects instead of direct values/rejected promises; this is the only current call contract, introduced in CHG-20261118-001.
  - ADAPT: Loom UI consumes schema metadata as JSON and displays it; business UI/handlers remain extension-owned.
  - NO-CHANGE: ST host and third-party extension interfaces; no ST files or unrelated extensions are modified.
  - CONFIRM: Actual ST reload, schema display, and execution result in browser to be recorded after testing.
- Architecture/API/data: Changes public capability invocation result shape and adds limited schema validation; registry remains in-memory and page-scoped.
- Compatibility/migration: No pre-existing stable Loom caller exists. Document the new result envelope in the API index before external adopters rely on 0.1.0 behavior.
- Validation:
  - `npm test`: pass, 6 tests covering schema validation, copy isolation, output mismatch, and handler exceptions.
  - `node --check "Loom Core/index.js"` and `node --check "Loom UI/index.js"`: pass.
  - ST page on port 8100 loaded Loom runtime version 0.2.0 with the Loom menu launcher.
  - Chrome browser registered a sample extension/capability: valid input returned `{ success: true, data }`; invalid input returned `INVALID_INPUT` with the missing property path.
  - Loom UI displayed and expanded the capability input schema; no Loom-related browser console errors.
  - Mobile/desktop viewport checks from prior baseline continued to apply to the panel structure; this change adds schema markup and responsive two-column/one-column layout.
- Failed checks and corrections: Initial test runs exposed missing unknown-keyword schema rejection and shared test registry cleanup. Both were corrected; preserve this note for traceability.
- Risks / outstanding: This is not full JSON Schema; unsupported keywords are rejected. No schema references/composition/formats, no permission sandbox, and trusted registered handlers still execute with page privileges.
- Related docs: `API_INDEX.md`, `ARCHITECTURE.md`, `PROJECT_STATE.md`.
