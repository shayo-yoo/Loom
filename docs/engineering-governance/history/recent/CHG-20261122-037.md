# CHG-20261122-037

- Date: 2026-11-22 (Asia/Shanghai)
- Type: FIX, TEST, DOCS
- Requirement / motivation: the user reported that clicking 停用 on a package (PC and phone) shows `hello-loom: Extension is already loaded` / `world-book-manager: Extension is already loaded`. They asked whether this is expected — it is not.
- Stage: user-reported defect.

## Root cause

The installer row wrote its toggle state into `data-enabled` using the **disabled** flag:

```js
data-enabled="${disabled}"   // label: disabled ? '启用' : '停用'
```

while the click handler interpreted that attribute as the *enabled* state:

```js
await setExtensionEnabled(id, toggle.dataset.enabled !== 'true')
```

So a row that was **active** (`disabled = false` → `data-enabled="false"`) produced `true` on click, i.e. it tried to **enable** the already-active extension. `setExtensionEnabled(true)` re-imported the package, Core refused the duplicate registration, and the error surfaced in the panel's problem list. The label said 停用, the action was 启用.

A second, smaller defect was hidden by the first: after a real unload the runtime state disappears, and `describeInstalled` fell back to the id, so a disabled row would have been renamed from "Hello Loom" to "hello-loom".

## Changes

- `data-enabled` now carries the **enabled** state (`!disabled`), matching the handler. The label and the attribute can no longer disagree.
- `setExtensionEnabled` is idempotent: disabling an already-unloaded package only records the choice, and enabling an already-active one only clears the flag, so a double click cannot reach the host.
- `describeInstalled` prefers the package's declared `name` over the runtime state, and `rememberInstalled` keeps `name`/`version`, so a disabled row keeps its display name. `installExtension` passes those fields through.
- The browser harness now drives the **real buttons**: it finds the row, clicks 停用, asserts the row becomes 已停用, the button flips to 启用, the display name is kept, and `getInstallProblems()` gains no "already loaded" entry; then clicks 启用 and asserts the extension is active again. This is the exact path the user exercised.

## Direct scope

`Loom UI/index.js`, `Loom UI/installer.js`, `Loom UI/installer.test.js`, `tests/browser/verify.mjs`, docs, version markers.

## Horizontal impact

- SYNC: `rememberInstalled` output shape gained `name`/`version`; its test was updated, and `describeInstalled` reads them.
- SYNC: manual installs now persist display metadata, so their rows also keep a name without the module loaded.
- NO-CHANGE: the script toggle already used the correct semantics (`data-enabled` = enabled) and was verified to still pass; package reload/remove; capability behaviour.

## Verification

- `npm test`: **244 tests pass** (the `rememberInstalled` test now covers the metadata fields).
- `npm run verify:browser`: **176/176 checks pass**, twice consecutively. New: real 停用/启用 clicks with no import error, row status and label updates, display name retained, and no new problems recorded.

## Risks / outstanding

- The problem list is in-memory only, so an old error disappears on reload — it cannot be mistaken for a current fault after a refresh.
- The row's state text and the runtime state are rendered from two sources (package metadata vs runtime); they are now consistent, but a future field added to one must be added to the other.
