# CHG-20261122-041

- Date: 2026-11-22 (Asia/Shanghai)
- Type: FEATURE, API, TEST, DOCS
- Requirement / motivation: the status review found that Loom could write data (world books, cards, chat) but could not influence what the model actually reads. "上下文注入" was the top item of the agreed list, and the requirements' extension-first model needs a permissioned, removable way to contribute to the prompt rather than letting extensions touch host internals.
- Stage: branch `feature/host-injection`, first batch.

## Capabilities

Three capabilities, all gated by a new permission `host.prompt.inject` that **no other capability declares** — an extension that can edit a world book is still not allowed to shape the prompt:

| Capability | Input | Output |
|---|---|---|
| `prompt.set` | `{ text, position?, depth?, role?, key? }` | `{ key, position, depth, role, length }` |
| `prompt.clear` | `{ key }` or `{ all: true }` | `{ cleared: [key] }` |
| `prompt.list` | — | `[{ key, position, depth, role, length, preview }]` |

## Isolation rules

- **Namespaced keys.** The caller's key `main` is stored in SillyTavern as `loom:<callerId>:main`. Two extensions cannot collide, and one cannot clear the other's entry (verified by test and by the browser probe).
- **Owner-scoped listing.** `prompt.list` returns only the caller's entries; other callers' entries are invisible even though the host map is shared.
- **Cleanup on unregister.** The first `prompt.set` for a caller registers one Core cleanup that deletes every key it wrote. A browser check injects, unregisters, and asserts the host map has no trace.
- **Read-back verification.** `setExtensionPrompt` returns nothing; the adapter reads `context.extensionPrompts[stKey]` back and fails with `PROMPT_INJECT_FAILED` when the host did not store the text, so a silent drop is never reported as success.

## Mirrored enums

`setExtensionPrompt` is exposed by `getContext()` but the position/role enums are not, so the numeric values are mirrored with the same deliberate duplication as the world-entry defaults (`in_prompt: 0`, `in_chat: 1`, `before_prompt: 2`; `system: 0`, `user: 1`, `assistant: 2`). A host upgrade that changes them must update this table.

Defaults: `position: 'in_chat'`, `depth: 4`, `role: 'system'`, `key: 'default'`. Text is capped at 20 000 characters and depth at 10 000, matching the host's `MAX_INJECTION_DEPTH`.

## Deliberately not done

`generation.before` / `generation.after` mutation hooks were part of the same list and are **not** implemented. SillyTavern emits `GENERATION_AFTER_COMMANDS` with a mutable options object, but the object's shape is internal and undocumented; wrapping it would produce a fragile contract that breaks on host updates. Observation is already available through the `host:generation:started` / `host:generation:ended` events. Recorded as an open item rather than half-implemented.

## Verification

- `npm test`: **259 tests pass** (+6: namespaced write and read-back, input validation and dropped-write detection, owner-scoped listing, clear one/all without touching another caller, permission gate with unregister cleanup, unsupported host).
- `npm run verify:browser`: **193/193 checks pass** (three consecutive runs). New: denied without the grant; the injection lands in the real `extensionPrompts` map with the mapped position/role numbers; `prompt.list` shows only the caller's entry; `prompt.clear` removes it; unregistering the owner leaves no trace.

## Risks / outstanding

- Injected text becomes part of the user's prompt: there is no size budget beyond 20 000 characters, and no UI that shows the user what an extension injected (`prompt.list` is caller-scoped by design, so the panel cannot display it either). A future consent-prompt extension should surface it.
- `depth` semantics belong to SillyTavern; Loom passes the number through without interpreting it.
- Generation-time mutation is not supported (see above).
