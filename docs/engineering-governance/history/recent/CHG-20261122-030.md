# CHG-20261122-030

- Date: 2026-11-22 (Asia/Shanghai)
- Type: FIX, TEST, DOCS
- Requirement / motivation: The user reported that every Loom button looked "thin and long", including the settings-drawer entry and the panel's permission toggles. A UI whose primary controls are unreadable is not acceptable, so this was investigated in the live page rather than guessed at.
- Stage: reported-defect fix, between P0 and the next capability increment.

## Diagnosis

Measured in a real SillyTavern page through the DevTools protocol instead of reading CSS:

- A permission toggle was **52 × 208 px** for the label "Hello Loom · 未授权" — the label had wrapped one word per line.
- The install button was 27 × 48 px, and the settings entry button could not be measured until its drawer was expanded.
- `CSS.getMatchedStylesForNode` on the toggle showed the cause: SillyTavern's own global rule **`.menu_button { width: min-content; display: flex; align-items: center; }`**. Every Loom button carries `menu_button`, so each shrank to its longest word and the rest of the label wrapped vertically.
- The wand-menu launcher was **not** affected (154 × 33 px): it is ST's list item markup, not a `menu_button`.

## Changes

`Loom UI/style.css`:

- `.loom_panel .menu_button`, `.loom_settings_open`, `#loom_installer .menu_button` now use `width: auto; max-width: 100%; flex: 0 0 auto; white-space: nowrap;` — intrinsic width, labels on one line, and no flex shrinking in a row.
- Icon-only header buttons keep their 44 × 44 tap target (`justify-content: center`).

Measured after the fix: settings entry **145 × 44**, permission toggle **206 × 28**, install **42 × 28**, header button **44 × 44**.

## Direct scope

`Loom UI/style.css`, `tests/browser/verify.mjs`.

## Horizontal impact

- SYNC: every Loom button uses `.menu_button`, so the rule is scoped to Loom containers rather than overriding ST globally — SillyTavern's own UI keeps its `min-content` behaviour.
- ADAPT: the harness gained a layout probe that measures the settings entry, the permission toggle, the install button and a header button, and fails if a button is narrower than 36 px or taller than 60 px (i.e. wrapped). The settings entry is measured with its ancestors temporarily revealed and then restored, because the drawer is collapsed by default.
- NO-CHANGE: button markup, labels, click handlers.

## Verification

- `npm test`: 237 tests pass (unchanged by the CSS fix).
- `npm run verify:browser`: **145/145 checks pass**, including the new layout probe and all previous checks.

## Risks / outstanding

- The rule is a CSS override of a host global; a SillyTavern release that renames `.menu_button` or changes the panel container class would need this revisited (the harness layout probe is the alarm).
- Long labels are now `nowrap`; an extremely long extension name in a permission toggle would overflow its row (capped by `max-width: 100%` but not truncated with an ellipsis).
