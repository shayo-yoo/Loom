# CHG-20261119-004

- Date: 2026-11-19 (Asia/Shanghai)
- Type: FEATURE, API, TEST, DOCS
- Requirement / motivation: Implement Core's event/state and lifecycle responsibilities by adding an extension-scoped event bus, disposal hooks, and a host event bridge, so extensions and UI can collaborate through public events instead of polling or private coupling.
- Changes:
  - Core: added `subscribe(extensionId, eventName, handler, { once })` returning an unsubscribe function; `emit(eventName, payload)` awaiting listeners in order and returning `{ delivered, errors }`; `listEvents()`; `addCleanup(extensionId, cleanup)` returning a remover.
  - Core: `unregisterExtension` now runs cleanup callbacks first, then removes the extension's listeners, capabilities, and registration. Its return value changed to `{ removed, cleanupErrors }`.
  - Core: `getRuntimeInfo()` now also reports `eventCount` and `listenerCount`.
  - Core: event names are validated and listeners are required to belong to a registered extension.
  - Core: added extension-scoped state storage (`getState`, `setState`, `deleteState`, `listStateKeys`), isolated per extension, dropped on unregister, and reported as `stateKeyCount` by `getRuntimeInfo()`.
  - Host: added an allowlisted SillyTavern event bridge (`CHAT_CHANGED`, `MESSAGE_SENT`, `MESSAGE_RECEIVED`, `CHARACTER_EDITED`, `WORLDINFO_UPDATED`, `GENERATION_STARTED`, `GENERATION_ENDED`) re-emitting Loom events `host:*` with only `{ source, event }` payloads; never forwards raw host arguments.
  - Host: bridge attaches lazily when the host is reachable, is idempotent, rolls back partial attachment on failure, and detaches itself through the Core cleanup hook.
  - UI: subscribes to the `host:*` events as `loom-ui`, refreshes the host snapshot when the panel is open, and renders an event-listener section plus an event-count row.
  - Bumped Core/manifest/package version to 0.4.0.
- Direct scope: `Loom Core/index.js`, `Loom Core/index.test.js`, `Loom Host/index.js`, `Loom Host/index.test.js`, `Loom UI/index.js`, `Loom UI/style.css`, `manifest.json`, `package.json`, governance docs.
- Horizontal impact:
  - SYNC: `unregisterExtension` callers must consume `{ removed, cleanupErrors }` instead of a boolean; the only callers are tests, updated in this change.
  - ADAPT: Host adapters now own host-event allowlists; new host events require an adapter update rather than Core changes.
  - NO-CHANGE: SillyTavern source and other extensions; the bridge only calls the public `eventSource.on/removeListener` API.
  - CONFIRM: Extension unload outside a page reload is not possible in SillyTavern today, so cleanup runs on explicit unregister or a full page reload only.
- Architecture/API/data: Adds a public event contract, extension-scoped state storage, and a disposal lifecycle. Events, listeners, and state are in-memory and page-scoped; listener failures are isolated and reported, not fatal. State is intentionally namespaced per extension rather than globally shared.
- Compatibility/migration: Event API is new. The `unregisterExtension` return-shape change is recorded here; no external stable caller exists at 0.x.
- Validation:
  - `npm test`: pass, 20 tests, including delivery order, `once`, unsubscribe, failure isolation, argument validation, cleanup execution/error reporting, per-extension state isolation and teardown, bridge forwarding, duplicate-listener avoidance, and detach-on-unregister.
  - `node --check` for Core, UI, and Host: pass.
  - ST page loaded runtime 0.4.0 with 7 bridged `host:*` events and 7 listeners; panel event section and event-count row matched `listEvents()`.
  - Firing a real ST `MESSAGE_RECEIVED`/`CHAT_CHANGED` through the host event source triggered a panel refresh, proven with a DOM `MutationObserver` (2 mutations on the host-status row); no Loom console errors.
- Failed checks and corrections: Two test cases failed initially for test-design reasons, not implementation reasons: `emit` argument validation rejects asynchronously, and the two bridge cases shared one module-level singleton bridge. The assertions were corrected and the bridge cases were merged into one end-to-end flow (attach, forward, dedupe, detach). No implementation change was required. Recorded for traceability.
- Risks / outstanding: No cross-extension shared state (by design; expose it through capabilities), no event payload schemas, no wildcard subscription, no cross-extension permission model, and no re-entrancy protection beyond snapshot iteration. State is not persisted across reloads. Bridge payloads intentionally omit host data, so consumers needing details must call a read capability.
