# CHG-20261122-035

- Date: 2026-11-22 (Asia/Shanghai)
- Type: FIX, TEST, DOCS
- Requirement / motivation: the user reported that Loom does not work on a phone-sized environment — the panel never appears. The previous mobile check had only measured geometry (width), so it passed while the panel was unrenderable.
- Stage: user-reported defect, fixed before the next increment.

## Reproduction

Reproduced under CDP mobile emulation (390×844, `mobile: true`, touch enabled):

- `#loom_panel` had `className="loom_panel open"`, `display: flex`, `position: fixed`, `inset: 0`, width 390 — and **height 0**.
- `document.elementFromPoint(195, 422)` returned a chat message, i.e. the panel was not hit-testable at all.
- Computed styles showed why: on phones SillyTavern sets `html { height: 0 }` and a **transform** (`matrix(1,0,0,1,0,0)`, identity but still a containing block), while `body` is `position: absolute; height: 844px`. A transformed root becomes the containing block for fixed descendants, so `inset: 0` resolved against a zero-height box and the panel collapsed.
- The manager's floating launcher used `bottom: 16px` and its panel `bottom: 72px`; the same zero-height containing block pushed both off screen (`top` would be negative).

The user's guess (panel anchored in the right-hand blank area that phones don't have) was close in effect but not the mechanism: the overlay is viewport-anchored, yet the host's transformed root broke that anchoring.

## Changes

- `.loom_panel` now states `height: 100vh` / `height: 100dvh` (and `min-height: 100vh`). Viewport units do not depend on the containing block, so the panel is full-height even with a zero-height transformed root.
- World-book manager: launcher moved from `bottom: 16px` to `top: calc(100dvh - 52px)` (with a `vh` fallback), and its panel from `bottom: 72px` to `top: 64px` with `max-height: calc(100dvh - 160px)`. Top anchoring is immune to the broken containing block.
- The mobile probe now asserts **visibility**, not just size: panel height ≥ 80% of the viewport, `panelTop === 0`, `elementFromPoint(centre)` inside the panel, manager panel and launcher fully inside the viewport, and no right-edge offenders. Touch emulation is enabled and cleared around the probe.

## Direct scope

`Loom UI/style.css`, `extensions/world-book-manager/index.js`, `tests/browser/verify.mjs`.

## Horizontal impact

- SYNC: the manager is the only other fixed-position consumer in the repo; its launcher and panel were both affected and are both fixed.
- ADAPT: the mobile probe measures the panel before opening the manager, because the manager (z-index 30000) sits above the Loom panel (10000) and would otherwise be the hit-test target.
- NO-CHANGE: desktop layout (100vh equals the previous `inset: 0` height there), capability code, scripts.

## Verification

- `npm test`: 244 tests pass (unchanged by the CSS fix; the count includes the new script-normalisation test from CHG-20261122-036).
- `npm run verify:browser`: **174/174 checks pass**, including the new visibility assertions: panel `390×844` at top 0 and hit-testable, manager `358×623` at top 64, launcher at 792–832 inside the 844 viewport.

## Risks / outstanding

- `100dvh` is newer than `100vh`; the fallback covers older browsers, and the unit depends on the visual viewport, so a soft keyboard may resize it. That interaction is still untested.
- Other SillyTavern screens may use different transformed containers; only the chat screen was emulated.
- Real devices remain untested: this is CDP emulation, not hardware.
